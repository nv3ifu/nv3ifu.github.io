CPU 后端流水线

在经过取指、解码为 μops、寄存器重命名、分配 ROB 条目后，μops 到达调度器。当数据就绪且执行端口空闲时，它就会被发射到后端的执行单元端口中：

  • INT Domain (整数域)：ALU 负责加减乘除、位运算、跳转计算
  • FLOAT/VEC Domain (浮点/向量域)：FPU/SIMD 单元负责浮点运算、AVX/SSE 指令
  • MEM Domain (访存域 / AGU)：地址生成单元，负责计算 MOV RAX, [RBP+8] 中的内存地址

同时还有并行的 LSU（Load/Store Unit），负责 Load/Store 操作，让 MMU 将 AGU 计算出来的地址翻译为物理地址，接着与 Cache/DRAM 交互，进行地址的读取写入。

超标量与端口瓶颈

我们知道现代 CPU 都是 超标量 的，也就是有多条流水线、多执行单元，来实现单核并行。

后端端口的数量是单核并行能力的一个瓶颈，尤其是在计算密集型任务中。

本机配置 i9-12900，分为性能核和能效核，它们分别是：

核心类型 微架构 Load 端口 Store 端口
性能核 Golden Cove 3 个 2 个
能效核 Gracemont 2 个 2 个

数据分析

根据测试出来的数据可以看到：

  • x1 → x2 → x3：基本是线性增长
  • x4：趋于平缓

那么它大概率是跑在了 性能核 上（3 个 Load 端口）。

Intel VTune Profiler 验证

使用 Intel VTune Profiler 查看硬件数据。

关键硬件事件统计（部分）：

Event P-Core E-Core

MEM_LOAD_RETIRED.L1_HIT 571,327,713,978 -
UOPS_DISPATCHED.PORT_2_3_10 579,306,868,959 -

结论

VTune 数据证实了我们的观点：程序 99.81% 运行在 P-Core (Golden Cove)。

从 UOPS_DISPATCHED.PORT_2_3_10 的数据（579B）与 Load 指令数量（579B）高度一致，验证了：

  • Golden Cove 的 Port 2/3/10 正是 3 个 Load 端口
  • x1 → x3 的线性增长符合 3 端口并行
  • x4 时饱和，因为只有 3 个端口可用
