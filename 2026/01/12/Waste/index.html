Waste

|Post Views:

本文为学习 Computer Enhance - Waste 的整理。

核心观点

提升程序性能只有两条路：

  1. 减少要求 CPU 执行的指令总数
  2. 调整这些指令，让它们更高效地穿过 CPU

除此之外，别无他法：要么减少数量，要么加快速度。

CPU 正在执行的指令中，存在大量指令，它们所做的事情，与实际程序逻辑毫无关系。

案例：计算 A + B

运行在两个较为极端的环境下：

  • C 语言：编译为原生机器码，运行在 CPU 上
  • Python：编译为字节码，运行在 CPython 虚拟机上（没有 JIT）

总结

这就是 “浪费 (Waste)”。

Python 要用 181 条指令 去完成本该 1 条指令 就能完成的工作。

这并不是说 Python 不好。Python 有着最接近自然语言的编程体验，在数学、AI 领域等有着不可替代的影响力。只是它的执行方式、JIT 的缺失，注定了它不会成为高性能场景下的选择。

不止 Python，有 JIT 的 Java，编译为机器码的 Go，执行速度都不及 C/C++，因为它们仍然拥有庞大的运行时，包括 GC、GMP、堆管理等等。
