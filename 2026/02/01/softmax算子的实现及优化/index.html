Softmax 简介

Softmax 的作用是将输入向量映射到一个所有元素值域在 [0, 1] 之间、且总和为 1 的概率分布上。

CPU 实现

CPU 版本是最基础的串行实现，每个大循环处理一行数据，主要分三个步骤：

  1. 求最大值：遍历当前行，找到最大值 maxval。
  2. 计算指数和求和：对每一项减去最大值后求指数 expf()，同时累加求和 sum，结果保存在输出数组中。
  3. 归一化：对输出数组中的每一项除以 sum。

可以看到它是完全串行的，循环中存在依赖链。

CUDA Kernel 1：朴素版本

最大的变化是每一行之间的操作变成并行的了。通过 if (i < N) 判断，一共有 N 个线程，每个线程负责处理一行。内存使用 cudaMalloc 申请，位于显存 (Global Memory) 中。

性能分析

在 Nsight Compute 中可以看到它的吞吐率非常低。原因还是并行度太低了——只有不同行之间的并行，一行数据仍然使用一个线程串行处理。

CUDA Kernel 2：共享内存 + Block 规约

我们为每一行数据仅分配了一个线程进行处理，其中一个线程串行处理一行，这导致了在输入张量第二维度上的并行度严重不足。

优化思路有三个：

  1. 线程粗化 (Thread Coarsening)：每个线程处理多个元素。
  2. 并行规约 (Parallel Reduction)：使用共享内存进行块内规约。
  3. 使用片上共享内存 (Shared Memory)：减少对全局显存的访问。

性能分析

原因分析：

“On average, each warp of this workload spends 48.7 cycles being stalled waiting for a scoreboard dependency on a L1TEX (local, global, surface, texture) operation. This stall type represents about 88.0% of the total average of 55.3 cycles between issuing two instructions.”

主要是全局显存的读取操作造成的等待：

通过汇编指令分析：右侧的 Warp Stall Sampling 显示第 73 行有一个巨大的长条（14.82%）。这表示 GPU 的采样器发现有大量的 Warp 就停在这行指令上。

这行指令是比较 R4 和 R3 的值。它必须等 R4 准备好才能执行。而 R4 来自第 63 行的 LDG.E R4, [R4.64]：

  • LDG = LoaD Global，这是标准的全局内存读取指令。
  • 它对应 C++ 代码中的 x[i] 读取操作。
  • 显存离核心很远，可能有几百个时钟周期的延迟。

CUDA Kernel 3：Warp Shuffle（仅 32 线程）

核心改进是用 Warp Shuffle 指令替换了共享内存通信。

但 Shuffle 指令只能在一个 Warp (32 线程) 内起作用，Thread Block 大小不能超过 32，这大大限制了线程块内部更大的并行潜力。

CUDA Kernel 4：Warp Shuffle + 跨 Warp 规约

核心差异：

  • Kernel 2：每个线程都把自己计算出来的局部最大值写入共享内存，然后进行规约。
  • Kernel 4：先使用 Warp Shuffle 在 Warp 内计算出最大值和求和结果，然后再将一个 Warp 的结果写入共享内存进行跨 Warp 规约。

这减少了共享内存的使用，转而使用 Warp 内的寄存器通信。共享内存只需要存储”每个 Warp 的结果”，而不是”每个线程的结果”。因为最大值（Max）和求和（Sum）各需要一份，所以共享内存大小为 2 * warpsPerBlock。

整体性能测试

测试环境：N=256, C=65536, blockSize=512

总结

Kernel 优化手段 加速比 (vs CPU)
Kernel 1 朴素并行（行间并行） 3.54x
Kernel 2 共享内存 + Block 规约 138.91x
Kernel 3 Warp Shuffle（仅 32 线程） 68.88x
Kernel 4 Warp Shuffle + 跨 Warp 规约 175.87x

Kernel 4 通过结合 Warp Shuffle 的低延迟通信和跨 Warp 规约，取得了最佳性能。
